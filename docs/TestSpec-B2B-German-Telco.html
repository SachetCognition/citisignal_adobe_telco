1. Introduction

This Test Specification defines the test cases for validating the B2B Telco Storefront for the German market, as specified in the User Requirements Specification (URS-B2B-DE-TELCO-2026). Each test case is mapped to one or more URS requirements to ensure full traceability and coverage.

2. Test Strategy

Test LevelTool / FrameworkScope
Unit Testing Jest / Mocha Individual block logic, utility functions, GraphQL query builders, validation helpers (IBAN, VAT ID, PLZ)
Integration Testing Cypress Component Testing Block interactions, Drop-in component integration, API response handling, event-bus communication
E2E Testing Cypress (existing setup in cypress/) Full user journeys: registration, catalog browsing, quote workflow, checkout, approval flows
Accessibility Testing axe-core, Lighthouse, Pa11y WCAG 2.1 AA compliance, BITV 2.0, keyboard navigation, screen reader compatibility
Performance Testing Lighthouse CI, WebPageTest, k6 LCP targets, concurrent user load, catalog search latency
Security Testing OWASP ZAP, manual review DSGVO compliance, RBAC enforcement, CSP headers, XSS prevention, data isolation

5. Company Account Tests (TC-CA-xxx)

TC-CA-001 Company Registration — Valid HRB & USt-IdNr P1 Planned

Maps to: URS-FR-001

Preconditions: VIES service available; no existing company with same HRB

Steps:

  1. Navigate to company registration page
  2. Enter valid company name, HRB number (e.g., HRB 12345), and USt-IdNr (e.g., DE123456789)
  3. Fill in all required fields (address, admin contact)
  4. Submit registration form

Expected Result: Registration succeeds. VIES validation passes. Company account is created with status “Pending Approval” or “Active”. Admin user receives confirmation email in German.

TC-CA-002 Company Registration — Invalid USt-IdNr P1 Planned

Maps to: URS-FR-001

Preconditions: VIES service available

Steps:

  1. Navigate to company registration page
  2. Enter valid company name and HRB, but invalid USt-IdNr (e.g., DE000000000)
  3. Submit registration form

Expected Result: VIES validation fails. Registration is rejected. German error message: “Ungültige USt-IdNr. Bitte überprüfen Sie Ihre Eingabe.”

TC-CA-003 Organizational Hierarchy — 3 Levels P1 Planned

Maps to: URS-FR-002

Preconditions: Company A is active with admin access

Steps:

  1. Log in as Company A admin
  2. Navigate to organization management
  3. Create hierarchy: Geschäftsführung → Abteilung IT → Team Entwicklung
  4. Assign users to each level

Expected Result: Three-level hierarchy is created and displayed correctly in the org tree. Users appear under their assigned organizational units.

TC-CA-004 Role Assignment — Buyer Permissions P1 Planned

Maps to: URS-FR-003

Preconditions: Company A active; admin and buyer users exist

Steps:

  1. Admin assigns “Buyer” role to user
  2. Log in as Buyer user
  3. Attempt to create an order → should succeed
  4. Attempt to approve a purchase order → should be denied

Expected Result: Buyer can browse catalog and create orders but cannot access approval workflows. Access denied message displayed in German.

TC-CA-005 German Address Management P2 Planned

Maps to: URS-FR-004

Preconditions: Company A active with admin access

Steps:

  1. Navigate to address management
  2. Add new address: Musterstraße 1, 10115, Berlin, Berlin
  3. Save address

Expected Result: Address saved with correct German format fields (Straße, PLZ, Ort, Bundesland). Address appears in address book and is selectable during checkout.

TC-CA-006 Credit Limit Enforcement P2 Planned

Maps to: URS-FR-005

Preconditions: Company A with Kreditlimit of 50.000 €; existing orders totaling 49.500 €

Steps:

  1. Log in as Buyer for Company A
